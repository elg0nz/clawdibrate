# MCP Tools — generate_metrics, identify_bugs, score, implement, calibrate

Expose the calibration pipeline as MCP tools, one per stage plus a one-call orchestrator.

## Context

Stages mirror `transcript → metrics → bug-identifier → judge → implementer`. Tools reuse
`metrics.py`, `orchestrator.py`, `modes.py`, `scores.py`, `prompts/*.md`. `implement` mutates the
file ONLY by system-calling the downscoped CLI (card 001). Model-backed tools use MCP sampling.
See SPEC.md Tools + decisions #3, #4.

## Acceptance Criteria

- [ ] `generate_metrics` — 5 Tier-1 metrics (`metrics.compute_metrics`), **zero model calls**
- [ ] `identify_bugs` — boundary violations/waste (`prompts/bug-identifier.md`), model via sampling
- [ ] `score` — failures→section attribution + composite weight; returns the Scorecard (card 008)
- [ ] `implement` — model decides new section content, then **system-calls `clawdibrate replace
      <section>` with content on stdin** (no in-process edit)
- [ ] `calibrate` — full loop, `mode=fast|progressive|max` (`orchestrator`/`modes.py`)
- [ ] Model-backed tools use MCP sampling; fallback to `CLAWDIBRATE_AGENT` adapter if unavailable
- [ ] No transcript/AGENTS.md data leaves the machine
