# Define Scorecard model-dependency boundary (no-model claim must be exact)

Specify which Scorecard fields are computed with zero model calls vs which require a model,
so the "self-hosted, no upload, no model call" claim in the post is precise and true.

## Context

The post says the five Tier-1 metrics run "with no model call." That is true for
`metrics.compute_metrics`. But the per-section VERDICT and TOP FIX use the judge/implementer
layer, which is model-backed. The release must not overclaim.

## Acceptance Criteria

- [ ] Document which Scorecard fields are model-free (Tier-1 metrics, scores, sparkline, deltas)
- [ ] Document which fields are model-backed (verdict strings, top-fix recommendation)
- [ ] Decide execution model for the model-backed layer: host-delegation vs MCP sampling vs spawned agent
- [ ] Confirm no transcript/AGENTS.md data leaves the machine in the chosen model
- [ ] Reconcile post copy with the decision (adjust "no model call" scoping if needed)
